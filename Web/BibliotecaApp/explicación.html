1. Introducción al proyecto

¿Qué es este proyecto?
Este proyecto, llamado BibliotecaApp, es una aplicación web diseñada para gestionar una biblioteca. Permite a los usuarios administrar libros, autores y los préstamos que se realizan.

¿Cuál es su objetivo y qué problema soluciona?
Su objetivo principal es reemplazar los registros manuales (en papel o Excel) de una biblioteca por un sistema automatizado. Resuelve el problema del desorden y la pérdida de información: ahora se puede saber exactamente qué libros hay, quién los escribió y si están prestados o disponibles.

¿Qué puede hacer?
El sistema permite crear, leer, actualizar y eliminar (operaciones conocidas como CRUD) la información de: Autores, Libros y Préstamos. Además, cuenta con un panel principal (Dashboard) que muestra estadísticas resumidas.

En términos sencillos: Es una página web a la que entras y ves botones para agregar libros nuevos, registrar a los autores de esos libros, y anotar a qué persona se le prestó un libro en específico. Todo esto se guarda de forma segura en una base de datos.

2. Tecnologías utilizadas

Este proyecto está construido con un conjunto de herramientas muy populares en el mundo del desarrollo web profesional.

C# (C Sharp)

¿Qué es? Un lenguaje de programación creado por Microsoft.
¿Para qué sirve? Es el cerebro del proyecto. Con C# se escriben las reglas lógicas: qué sucede cuando el usuario hace clic en "Guardar", cómo se calcula la fecha de devolución, etc.
Ejemplo: public string Titulo { get; set; } (Una línea de C# que dice que los libros tendrán un Título).

ASP.NET Core MVC

¿Qué es? Un "Framework" (un marco de trabajo) para C#. Es como una plantilla gigante que ya trae muchas herramientas prefabricadas para hacer páginas web.
¿Para qué sirve? Organiza el proyecto en tres partes: Modelos (Datos), Vistas (Pantallas) y Controladores (Intermediarios). Por eso se llama "MVC".

Entity Framework Core (EF Core)

¿Qué es? Un "ORM" (Mapeador Objeto-Relacional).
¿Para qué sirve? Es un traductor. C# habla en "objetos" y las bases de datos hablan en "tablas y SQL". EF Core se encarga de traducir automáticamente entre ambos. Así, no tienes que escribir código SQL complejo manualmente.

SQL Server (LocalDB)

¿Qué es? El sistema de Base de Datos.
¿Para qué sirve? Es un almacén digital donde se guarda toda la información (los nombres de los libros, los autores) para que no se borre cuando se apaga el computador.

HTML, CSS y Razor

¿Qué son? Los lenguajes para diseñar la cara del sitio web.
HTML crea los textos y botones. CSS les da color y forma. Razor (archivos .cshtml) permite mezclar HTML con C#, para por ejemplo, mostrar una lista de libros directamente desde la base de datos a la pantalla.

3. Estructura de carpetas

Los proyectos profesionales tienen un orden estricto. Así está organizado este proyecto:

BibliotecaApp/
│
├── Controllers/     ← Intermediarios (Los meseros del restaurante)
├── Models/          ← Definición de datos (Los ingredientes)
├── Views/           ← Lo que ve el usuario (La presentación del plato)
├── ViewModels/      ← Datos empaquetados específicamente para las Vistas
├── Services/        ← La lógica de negocio (Los cocineros)
├── Data/            ← Conexión a la base de datos (La bodega)
├── wwwroot/         ← Archivos públicos (Imágenes, CSS, JS)
├── Program.cs       ← El punto de inicio de toda la aplicación
└── appsettings.json ← Configuraciones (Como contraseñas de la base de datos)

¿Por qué esta organización?
Se llama Arquitectura de Software. Separa las responsabilidades. Si quieres cambiar el color de un botón, vas a Views. Si quieres cambiar cómo se guarda un libro, vas a Services. Si todos estuviera en un solo archivo, sería imposible de entender o mantener.

4. Explicación archivo por archivo

Vamos a analizar los archivos más importantes que hacen que esta aplicación funcione.

📁 Program.cs

Función: Es el corazón y punto de partida de la aplicación. Cuando ejecutas el proyecto, este es el primer archivo que lee el computador.

Qué contiene: Contiene la configuración inicial. Aquí se le dice al sistema: "Vamos a usar una base de datos", "Vamos a usar el patrón MVC", y se registran los "Servicios" (Inyección de dependencias).

Código clave:
builder.Services.AddDbContext<ApplicationDbContext>(...) (Conecta la base de datos).
builder.Services.AddScoped<ILibroService, LibroService>(); (Enseña a la aplicación dónde está la lógica de los libros).

📁 Data / ApplicationDbContext.cs

Función: Es el puente de comunicación directo entre tu código de C# y tu base de datos SQL.

Qué contiene: Define las "tablas" que existirán en la base de datos usando algo llamado DbSet. También configura cómo se relacionan las tablas entre sí.

Código clave:
public DbSet<Libro> Libros { get; set; }
Esto le dice a la base de datos: "Crea una tabla llamada Libros, y ponle columnas según lo que diga el archivo Libro.cs".

📁 Models / Libro.cs

Función: Define qué es un "Libro" en el sistema.

Qué contiene: Propiedades simples como Id, Titulo, ISBN y AnioPublicacion. También contiene las relaciones: Un libro pertenece a un Autor, y un libro puede tener muchos Préstamos.

Con qué se relaciona: Este archivo es usado por la base de datos para crear las columnas, y por los servicios para guardar información.

📁 Services / LibroService.cs

Función: Contiene la "Lógica de Negocio". Es el cerebro de las operaciones de los libros.

Qué contiene: Funciones complejas como ObtenerTodosAsync o CrearLibroAsync. Si alguien quiere buscar los libros que están "Prestados", la búsqueda se hace aquí, no en la vista.

Cómo funciona: Recibe la base de datos (ApplicationDbContext), busca la información, la filtra, la organiza y se la entrega al controlador lista para usar.

📁 Controllers / LibrosController.cs

Función: Es el director de tráfico. Atiende las peticiones del usuario que llegan desde el navegador web.

Cómo funciona: Cuando el usuario entra a www.tusitio.com/Libros, este controlador se activa. Llama al LibroService para pedirle la lista de libros, y luego le pasa esa lista a la carpeta Views para que dibuje la página web y se la envíe al usuario.

📁 ViewModels / CrearEditarLibroViewModel.cs

Función: Es un "mensajero".

Por qué se usa: En lugar de enviar todo el Modelo Libro.cs completo a la pantalla, se crea un "ViewModel" que solo contiene la información estricta y necesaria para crear o editar un libro. Esto hace que la aplicación sea más segura y rápida.

6. Explicación del código

Vamos a desglosar fragmentos reales de código del proyecto para entenderlos línea por línea.

Variables y Propiedades (En Models/Libro.cs)

public class Libro
{
    public int Id { get; set; }
    public string Titulo { get; set; } = string.Empty;
}
  • public: Significa que cualquier otra parte del sistema puede leer esto.
  • int: Es un tipo de dato. Significa "Número entero". El ID (identificador) será un número como 1, 2, 3...
  • string: Significa "Cadena de texto". El Título será texto (ej. "Cien años de soledad").
  • { get; set; }: Significa que el programa puede obtener (get) el valor y también modificarlo (set).

Controladores y Peticiones (En Controllers/LibrosController.cs)

[HttpPost]
public async Task<IActionResult> Create(CrearEditarLibroViewModel viewModel)
{
    if (ModelState.IsValid)
    {
        await _libroService.CrearLibroAsync(viewModel);
        return RedirectToAction(nameof(Index));
    }
    return View(viewModel);
}
  • [HttpPost]: Esto es un escudo de seguridad. Significa que esta función solo se activa si el usuario está enviando un formulario (POST), no si solo escribe la dirección en el navegador.
  • async / await: Significa "Asíncrono". Le dice al servidor: "Voy a guardar esto en la base de datos, va a demorar unas milésimas de segundo, tú atiende a otras personas mientras termino". Hace que el sistema no se congele.
  • ModelState.IsValid: Revisa si el usuario llenó bien el formulario (ej. que no haya dejado el título en blanco).
  • RedirectToAction("Index"): Si todo salió bien, redirige al usuario de vuelta a la lista de libros principal.

Consultas a Bases de datos (En Services/LibroService.cs)

var query = _context.Libros
    .Include(l => l.Autor)
    .Where(l => !l.Prestamos.Any(p => p.FechaDevolucion == null))
    .ToList();

Qué hace esto: Esto es "LINQ", la forma mágica de C# de hablar con la base de datos.

  1. _context.Libros: Entra a la tabla de libros.
  2. .Include(l => l.Autor): Trae también la información del Autor (para que no salga solo el ID del autor, sino su nombre).
  3. .Where(...): Filtra los resultados. En español dice: "Tráeme los libros DONDE no exista ningún préstamo que tenga la Fecha de Devolución en blanco". Es decir, busca los libros que sí están Disponibles.

7. Base de datos

El proyecto utiliza una base de datos Relacional. Imagina una base de datos como un gran libro de Excel con varias hojas conectadas entre sí. A cada hoja se le llama Tabla.

El proyecto tiene 3 tablas principales:

Tabla: Autores

  • Id (Clave Primaria): Número único (ej. 1)
  • Nombre: Texto (ej. "Gabriel García")
  • Nacionalidad: Texto (ej. "Colombia")

Tabla: Libros

  • Id (Clave Primaria): Número único (ej. 5)
  • Titulo: Texto (ej. "El Coronel")
  • AutorId (Clave Foránea): Apunta al Autor (ej. 1)

Tabla: Prestamos

  • Id: Número único
  • LibroId (Clave Foránea): Qué libro se prestó
  • NombrePrestatario: A quién se prestó
  • FechaDevolucion: Cuándo lo entregó

Relaciones:

  • Clave Primaria (Primary Key - PK): Es como el número de cédula o DNI de cada fila. Nunca se repite. Todos los Id son claves primarias.
  • Clave Foránea (Foreign Key - FK): Es un puente que une dos tablas. La columna AutorId en la tabla Libros sirve para no tener que escribir "Gabriel García" en 100 libros. Solo se escribe el número "1", y el sistema sabe que el libro pertenece al autor número 1.

8. HTTP y Comunicación (El Navegador y el Servidor)

Aunque esto no es una API pura (porque devuelve HTML y no datos crudos), la comunicación usa las reglas universales del internet: el protocolo HTTP.

Hay dos tipos principales de peticiones que hace este proyecto:

Método HTTP ¿Para qué se usa en el proyecto? Ejemplo real
GET Para pedir información. No cambia nada en la base de datos. Solo "lee". Cuando haces clic en "Editar", el navegador hace un GET /Libros/Edit/5 para pedir el formulario del libro 5.
POST Para enviar información. Modifica la base de datos (crea o actualiza). Cuando llenas el formulario y presionas "Guardar", se hace un POST /Libros/Create enviando los datos ocultos.
¿Qué es un Endpoint / Ruta?
Es la dirección (URL). En este proyecto las rutas se construyen así: Controlador / Acción / Id.
Ejemplo: tusitio.com/Libros/Delete/3
Esto le dice al sistema: Ve al archivo LibrosController, ejecuta la función Delete, para el elemento con el número 3.

9. Flujo de una acción real: Crear un Préstamo

Imaginemos que Juan quiere llevarse prestado el libro "1984". Esto es exactamente lo que ocurre internamente en la aplicación, paso a paso:

  1. El bibliotecario hace clic en el botón "Nuevo Préstamo".
  2. El navegador web hace una petición GET a la ruta /Prestamos/Create.
  3. El archivo PrestamosController.cs recibe la petición. Ejecuta la función Create().
  4. Dentro de esa función, el sistema va a la base de datos y busca la lista de todos los libros disponibles para poder llenar un menú desplegable (Select).
  5. El controlador devuelve la pantalla (Vista) HTML Create.cshtml con el menú cargado.
  6. El bibliotecario selecciona el libro "1984", escribe el nombre "Juan" y hace clic en Guardar.
  7. El navegador junta esos datos y los envía empaquetados mediante una petición POST de vuelta a /Prestamos/Create.
  8. El controlador recibe el paquete (llamado CrearEditarPrestamoViewModel). Revisa que todo esté correcto (ej. que el nombre no esté vacío).
  9. El controlador le pasa los datos a PrestamoService.cs.
  10. El servicio crea un nuevo objeto "Prestamo" en memoria, le asigna la fecha de hoy automáticamente, y le dice al ApplicationDbContext que lo guarde.
  11. Entity Framework traduce esto a SQL (ej. INSERT INTO Prestamos...) y lo guarda permanentemente en SQL Server.
  12. El controlador responde al navegador con una instrucción: "Todo salió bien, ahora redirige al usuario a la página de inicio (Index)".
  13. El bibliotecario ve la lista principal y nota que ahora aparece el préstamo de Juan.

10. Errores y posibles problemas

Si intentas modificar o ejecutar el proyecto por primera vez, podrías encontrarte con estos obstáculos:

Problema: No se puede conectar a la Base de Datos

Causa: El archivo appsettings.json tiene una "Cadena de Conexión" que dice Server=(localdb)\mssqllocaldb. Esto asume que tienes instalado SQL Server Express LocalDB en tu computador.

Solución: Si estás en un Mac o usas otro tipo de servidor, debes cambiar esa línea por la ruta correcta de tu base de datos, o instalar las herramientas de desarrollo de SQL de Visual Studio en tu Windows.

Problema: La tabla 'Libros' no existe (Error de SQL)

Causa: El código define las tablas, pero no has ejecutado el comando para que la base de datos física las construya.

Solución: Tienes que ejecutar las "Migraciones" de Entity Framework. Las migraciones son las instrucciones paso a paso para crear las tablas desde cero.

Problema: Archivos no encontrados (Error 404)

Causa: Borraste o cambiaste el nombre de una vista en la carpeta Views (ej. cambiaste Index.cshtml a Lista.cshtml) pero el controlador sigue intentando abrir "Index".

Solución: En MVC, el nombre del archivo en la carpeta Views debe coincidir EXACTAMENTE con el nombre de la función (Acción) en el Controlador, a menos que especifiques lo contrario en el código.

11. Instalación y ejecución

Para encender el proyecto en tu computador desde cero, debes seguir estos pasos en la terminal (línea de comandos) estando dentro de la carpeta BibliotecaApp\BibliotecaApp.

# 1. Requisitos
Debes tener instalado el SDK de .NET (versión 8 o 9) y SQL Server LocalDB.

# 2. Restaurar dependencias
# Esto descarga de internet todas las herramientas externas que usa el proyecto
dotnet restore

# 3. Crear la base de datos
# Entity Framework leerá tus modelos (Libros, Autores) y creará las tablas físicamente.
dotnet ef database update

# 4. Iniciar el servidor
# Esto compila el código C# y arranca un servidor web local.
dotnet run

Cómo comprobar que funciona:
Después de ejecutar dotnet run, la terminal te dirá algo como: "Now listening on: http://localhost:5000". Copia esa dirección, pégala en Chrome, y deberías ver la página principal de la Biblioteca. El proyecto cuenta con un archivo DbSeeder.cs que insertará datos falsos de prueba automáticamente la primera vez que inicie, así que no verás el sistema vacío.

12. Conceptos que debo aprender

Si quieres volverte un experto y poder modificar esta aplicación a tu antojo, este es tu mapa de estudio:

🟢 Nivel básico (Lo primero que debes buscar en YouTube)

  • HTML y CSS básicos: Cómo crear una etiqueta <div>, un formulario, y cómo cambiar colores.
  • Programación Orientada a Objetos (POO): Entender qué es una Clase (ej. class Libro) y qué es un Objeto (Un libro físico en específico).

  • C# Básico: La sintaxis del lenguaje.
  • El patrón MVC (Modelo-Vista-Controlador): Cómo interactúan estas tres piezas y cómo fluyen los datos entre ellas.
  • Entity Framework Core: Cómo conectar C# con SQL. Aprender qué es un DbSet y cómo hacer un .Where() o .Include() (LINQ).
  • Inyección de Dependencias: Entender por qué se usa builder.Services.AddScoped en el archivo Program.cs.

🔴 Nivel avanzado (Para crear proyectos gigantes)

  • Programación Asíncrona (async/await): Cómo hacer que tu programa ejecute tareas en segundo plano sin congelar la pantalla.
  • El patrón Repository o Arquitectura de Capas: Aunque este proyecto usa "Servicios", hay formas más avanzadas de organizar bases de datos gigantescas.
  • Autenticación y JWT: Cómo agregar un sistema de Login para que solo administradores puedan borrar libros.

13. Glosario

Concepto técnico Explicación sencilla
Frontend La cara visible del proyecto. Los botones, colores y tablas que ve el usuario en su pantalla (HTML/CSS).
Backend El motor invisible. Todo lo que ocurre detrás: cálculos lógicos, seguridad y acceso a la base de datos (C#).
Framework Una caja de herramientas o plantilla preconstruida (ASP.NET Core) para no empezar a programar desde cero.
Middleware Pequeños guardias de seguridad que inspeccionan las peticiones que llegan al servidor antes de dejarlas entrar al controlador.
Query / Consulta Una pregunta o instrucción que se le hace a la base de datos. Ej: "Tráeme todos los libros del año 2000".
Vista (View) Un archivo de interfaz gráfica (.cshtml). Es una plantilla HTML que puede imprimir variables de C# en la pantalla.

14. Resumen final

La BibliotecaApp es una aplicación web clásica, construida con C# y ASP.NET Core.

Funciona bajo un patrón de organización llamado MVC. Cuando un usuario interactúa con la página (Frontend), su navegador envía una señal al servidor. Esta señal es recibida por un Controlador, quien delega el trabajo pesado a los Servicios. Los servicios se conectan a una base de datos SQL Server mediante un traductor llamado Entity Framework Core.

Una vez que el servicio rescata la información (por ejemplo, la lista de libros), la empaqueta (ViewModels) y se la devuelve al Controlador. El Controlador toma ese paquete, se lo inserta a una plantilla de diseño (Vista), y esa Vista es lo que finalmente viaja por internet de regreso al monitor del usuario.

Para modificar el sistema, necesitas dominar C# para cambiar la lógica en el servidor, HTML/CSS para cambiar cómo se ve en pantalla, y entender conceptos básicos de Bases de Datos para añadir nueva información al registro.
