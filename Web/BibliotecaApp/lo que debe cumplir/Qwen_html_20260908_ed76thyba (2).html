➕ Create de Autor

Arquitectura en Capas con Services + ViewModels

🎉 ¡Buenas noticias! Ya tenemos el ViewModel

En el paso anterior (Edit) creamos el CrearEditarAutorViewModel. Ese mismo ViewModel sirve para el Create, porque el formulario es idéntico.

Así que NO necesitamos crear ningún ViewModel nuevo. Solo vamos a:

  1. Agregar métodos al servicio
  2. Modificar el controlador
  3. Modificar la vista

🧠 Explicación simple para tus aprendices

El Create es el más simple de todas las acciones:

📝 CREATE GET

Solo muestra un formulario vacío. No necesita buscar nada en la base de datos.

💾 CREATE POST

Recibe los datos del formulario y crea un nuevo registro en la base de datos.

Es como llenar un formulario en papel: GET te da el formulario vacío, POST lo envía para que lo procesen.

🔄 Flujo del Create

GET (cuando el usuario hace clic en "Crear Nuevo")

1. Usuario hace clic en "Crear Nuevo"
Navegador envía GET a /Autor/Create
↓

Crea un ViewModel vacío y lo pasa a la vista
↓
3. Vista Create

POST (cuando el usuario hace clic en "Crear")

1. Usuario llena el formulario y hace clic en "Crear"
Navegador envía POST con los datos del formulario
↓
2. Controlador Create POST
Recibe el ViewModel, valida con ModelState.IsValid
↓

↓
4. Redirección
Vuelve al Index con el nuevo autor en la lista

💡 ¿Por qué solo un método?

Porque el Create GET es tan simple que no necesita un método del servicio. Solo crea un ViewModel vacío en el controlador. El Create POST sí necesita un método porque crea un registro en la base de datos.

2 Implementar el método en el Servicio

Services/AutorService.cs

¿Dónde? Abrir Services/AutorService.cs y agregar este método al final (no borrar los que ya existen).

// ✅ AGREGAR ESTE MÉTODO (dentro de la clase AutorService):

public async Task<bool> CrearAutorAsync(CrearEditarAutorViewModel viewModel)
{
    // Crear un nuevo objeto Autor a partir del ViewModel
    var autor = new Autor
    {
        Nombre = viewModel.Nombre,
        Nacionalidad = viewModel.Nacionalidad,
        FechaNacimiento = viewModel.FechaNacimiento
    };

    // Agregarlo a la base de datos
    _context.Autores.Add(autor);
    
    // Guardar los cambios
    await _context.SaveChangesAsync();

    return true;
}
💡 ¿Qué hace este método, línea por línea?
  1. var autor = new Autor { ... } → Creamos un nuevo objeto Autor (modelo de dominio) y copiamos los datos del ViewModel. El Id NO se asigna porque la base de datos lo genera automáticamente.
  2. _context.Autores.Add(autor) → Le decimos a Entity Framework: "agrega este nuevo autor a la tabla Autores".
  3. await _context.SaveChangesAsync() → Ejecutamos el INSERT en la base de datos. Aquí es cuando se genera el Id automáticamente.
  4. return true → Devolvemos true para indicar que todo salió bien.
💡 ¿Por qué no devolvemos el autor creado?

Porque después de crearlo, redirigimos al Index. El Index va a buscar todos los autores de nuevo, así que no necesitamos devolver el autor recién creado. Si en el futuro necesitas mostrar un mensaje de éxito con el nombre del autor creado, puedes cambiar el método para que devuelva el Id o el objeto completo.

3 Modificar los métodos Create del Controlador

Controllers/AutorController.cs

¿Dónde? Abrir Controllers/AutorController.cs y reemplazar SOLO los dos métodos Create (GET y POST). Los demás métodos NO se tocan.

Create GET (mostrar el formulario vacío):

public IActionResult Create()
{
    return View();
}

✅ REEMPLAZAR CON ESTO

// GET: AUTORS/Create
public IActionResult Create()
{
    // Crear un ViewModel vacío
    var viewModel = new CrearEditarAutorViewModel();
    return View(viewModel);
}

Create POST (guardar el nuevo autor):

❌ BORRAR ESTO (el Create POST viejo)

[HttpPost]
[ValidateAntiForgeryToken]
public async Task<IActionResult> Create(
    [Bind("Id,Nombre,Nacionalidad,FechaNacimiento")] 
    Autor autor)
{
    if (ModelState.IsValid)
    {
        _context.Add(autor);
        await _context.SaveChangesAsync();
        return RedirectToAction(nameof(Index));
    }
    return View(autor);
}

✅ REEMPLAZAR CON ESTO

// POST: AUTORS/Create
[HttpPost]
[ValidateAntiForgeryToken]
public async Task<IActionResult> Create(
    CrearEditarAutorViewModel viewModel)
{
    if (!ModelState.IsValid)
    {
        return View(viewModel);
    }

    await _autorService.CrearAutorAsync(viewModel);
    return RedirectToAction(nameof(Index));
}
💡 ¿Qué cambió en el Create GET?
Antes Ahora
return View(); (sin parámetro) return View(viewModel); (con ViewModel vacío)
💡 ¿Por qué creamos un ViewModel vacío?

Porque la vista espera recibir un CrearEditarAutorViewModel. Si no le pasamos nada, la vista va a tener un Model nulo y va a fallar cuando intente acceder a Model.Nombre, Model.Nacionalidad, etc. Al crear un ViewModel vacío, la vista puede mostrar el formulario sin errores.

💡 ¿Qué cambió en el Create POST?
Antes Ahora
Recibía un Autor con [Bind(...)] Recibe un CrearEditarAutorViewModel
Usaba _context.Add(autor) Llama a _autorService.CrearAutorAsync(viewModel)
La lógica de creación estaba en el controlador La lógica de creación está en el servicio
💡 ¿Por qué ya no necesitamos [Bind(...)]?

¡Porque el ViewModel ya es seguro por diseño! Solo tiene 3 propiedades: Nombre, Nacionalidad, FechaNacimiento. No tiene Id, no tiene Libros, no tiene nada peligroso. Aunque un hacker intente enviar datos extra, el Model Binder los va a ignorar porque el ViewModel no los tiene.

💡 ¿Por qué la vista es idéntica a la del Edit?

Porque el formulario es exactamente el mismo: los mismos campos, las mismas validaciones. La única diferencia es el título (Crear Nuevo Autor vs Editar Autor) y el texto del botón (Crear vs Guardar). El asp-action también es diferente (Create vs Edit).

Esto es una ventaja de usar ViewModels: puedes reutilizar el mismo ViewModel para varias acciones cuando el formulario es idéntico.

🎯 ¿Qué aprendieron tus aprendices?

  • El Create GET es muy simple → Solo crea un ViewModel vacío y lo pasa a la vista. No necesita buscar nada en la base de datos.
  • El Create POST delega al servicio → El controlador solo valida y llama al servicio. El servicio es el que crea el registro en la base de datos.
  • Un ViewModel puede reutilizarse → CrearEditarAutorViewModel sirve tanto para Create como para Edit porque el formulario es idéntico.
  • El Id lo genera la base de datos → No necesitamos asignarlo manualmente. Entity Framework lo hace automáticamente cuando llamamos a SaveChangesAsync().
  • Las vistas de Create y Edit son casi idénticas → Solo cambian el título, el texto del botón y el asp-action. Podrías crear una vista parcial compartida si quisieras.
  • Ya no necesitamos [Bind(...)] → El ViewModel es seguro por diseño.
