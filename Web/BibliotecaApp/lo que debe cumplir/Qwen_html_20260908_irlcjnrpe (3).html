📖 Details de Autor

Arquitectura en Capas con Services + ViewModels

🧠 Explicación simple para tus aprendices

El Index muestra una lista de muchos autores con datos resumidos.

El Details muestra la información completa de UN solo autor, incluyendo sus libros.

Es como la diferencia entre ver la portada de un libro (Index) y abrir el libro y leerlo (Details).

Por eso necesitamos un ViewModel diferente: el del Index solo necesita 5 campos. El del Details necesita más información (como la lista de títulos de sus libros).

🔨 Implementación Paso a Paso

1 Crear el ViewModel para Details

ViewModels/AutorDetalleViewModel.cs

¿Dónde? Clic derecho sobre la carpeta ViewModels → Agregar → Clase → nombrar AutorDetalleViewModel.cs

namespace BibliotecaApp.ViewModels
{
    public class AutorDetalleViewModel
    {
        public int Id { get; set; }
        public string Nombre { get; set; } = string.Empty;
        public string Nacionalidad { get; set; } = string.Empty;
        public DateTime? FechaNacimiento { get; set; }
        public int TotalLibros { get; set; }
        public List<string> TitulosLibros { get; set; } = new List<string>();
    }
}
💡 ¿Por qué un ViewModel diferente al del Index?

Porque el Index y el Details muestran cosas diferentes:

Campo Index (lista) Details (uno solo)
Id ✅ Sí ✅ Sí
Nombre ✅ Sí ✅ Sí
Nacionalidad ✅ Sí ✅ Sí
FechaNacimiento ✅ Sí ✅ Sí
TotalLibros ✅ Sí ✅ Sí
TitulosLibros ❌ No (sería mucho dato para una tabla) ✅ Sí (aquí sí tiene sentido mostrarlos)

El Index es como ver las filas de una tabla: solo lo esencial.
El Details es como abrir la ficha completa: todo el detalle.

💡 ¿Por qué List<string> y no List<Libro>?

Porque la vista solo necesita mostrar los títulos de los libros. No necesita el ISBN, el año, el autor, etc. Pasar solo strings es más seguro y más ligero. El ViewModel le da a la vista exactamente lo que necesita, ni más ni menos.

2 Agregar el método a la Interfaz del Servicio

Services/IAutorService.cs

¿Dónde? Abrir Services/IAutorService.cs y agregar UNA línea (no borrar lo que ya existe).

using BibliotecaApp.ViewModels;

namespace BibliotecaApp.Services
{
    public interface IAutorService
    {
        Task<IEnumerable<AutorIndexViewModel>> ObtenerTodosAsync(string? buscar);
        
        // ✅ AGREGAR ESTA LÍNEA:
        Task<AutorDetalleViewModel?> ObtenerDetalleAsync(int id);
    }
}
💡 ¿Por qué? La interfaz es el contrato. Antes solo decía: "Sé buscar todos los autores". Ahora también dice: "Sé buscar UN autor por su id y devolverlo como detalle".
💡 ¿Por qué devuelve AutorDetalleViewModel? con el signo ??

Porque si le pides un autor con un id que no existe (por ejemplo, id = 999), no hay nada que devolver. El ? significa que puede devolver null. El controlador se encargará de convertir ese null en un error 404 (página no encontrada).

3 Implementar el método en el Servicio

Services/AutorService.cs

¿Dónde? Abrir Services/AutorService.cs y agregar este método al final (no borrar el método ObtenerTodosAsync que ya existe).

// ✅ AGREGAR ESTE MÉTODO NUEVO (dentro de la clase AutorService):
public async Task<AutorDetalleViewModel?> ObtenerDetalleAsync(int id)
{
    var autor = await _context.Autores
        .Include(a => a.Libros)
        .FirstOrDefaultAsync(a => a.Id == id);

    if (autor == null)
    {
        return null;
    }

    return new AutorDetalleViewModel
    {
        Id = autor.Id,
        Nombre = autor.Nombre,
        Nacionalidad = autor.Nacionalidad,
        FechaNacimiento = autor.FechaNacimiento,
        TotalLibros = autor.Libros.Count,
        TitulosLibros = autor.Libros.Select(l => l.Titulo).ToList()
    };
}
💡 ¿Qué hace este método, línea por línea?
  1. _context.Autores → Va a la tabla de autores en la base de datos.
  2. .Include(a => a.Libros) → También trae los libros de ese autor (sin esto, la lista de libros vendría vacía).
  3. .FirstOrDefaultAsync(a => a.Id == id) → Busca el primer autor que coincida con el id. Si no encuentra ninguno, devuelve null.
  4. if (autor == null) return null; → Si no existe, salimos temprano. No hay nada que hacer.
  5. return new AutorDetalleViewModel { ... } → Creamos el ViewModel y copiamos los datos del modelo al ViewModel. Esto se llama mapeo manual.
  6. TotalLibros = autor.Libros.Count → Contamos cuántos libros tiene. Es un dato calculado, no una columna de la base de datos.
  7. TitulosLibros = autor.Libros.Select(l => l.Titulo).ToList() → De todos los libros, extraemos solo el título de cada uno y lo convertimos en una lista de strings.

4 Modificar el método Details del Controlador

Controllers/AutorController.cs

¿Dónde? Abrir Controllers/AutorController.cs y reemplazar SOLO el método Details (los demás métodos NO se tocan).

❌ BORRAR ESTO (el método Details viejo)

public async Task<IActionResult> Details(int? id)
{
    if (id == null) return NotFound();

    var autor = await _context.Autores
        .Include(a => a.Libros)
        .FirstOrDefaultAsync(m => m.Id == id);

    if (autor == null) return NotFound();

    return View(autor);
}

✅ REEMPLAZAR CON ESTO (el nuevo)

public async Task<IActionResult> Details(int? id)
{
    if (id == null)
    {
        return NotFound();
    }

    var detalle = await _autorService
        .ObtenerDetalleAsync(id.Value);

    if (detalle == null)
    {
        return NotFound();
    }

    return View(detalle);
}
💡 ¿Qué cambió?
Antes Ahora
Usaba _context directamente Usa _autorService
Hacía la consulta con .Include().FirstOrDefaultAsync() Llama a .ObtenerDetalleAsync()
Devolvía View(autor) (modelo de dominio) Devuelve View(detalle) (ViewModel)
💡 ¿Por qué id.Value?

Porque el parámetro id es int? (nullable, puede ser nulo). Pero en la línea de arriba ya verificamos que no es nulo (if (id == null) return NotFound()). Así que cuando llegamos a _autorService.ObtenerDetalleAsync(id.Value), sabemos con certeza que id tiene un valor. El .Value extrae ese valor del nullable.

🎯 ¿Qué aprendieron tus aprendices?

  • Cada vista tiene su propio ViewModel → El Index usa AutorIndexViewModel, el Details usa AutorDetalleViewModel. Son diferentes porque muestran cosas diferentes.
  • El servicio hace el trabajo pesado → Busca en la base de datos, calcula datos (TotalLibros), y arma el ViewModel. El controlador solo llama y devuelve.
  • El ViewModel le da a la vista solo lo que necesita → TitulosLibros es una lista de strings, no de objetos completos. Menos datos = más seguridad y mejor rendimiento.
  • El null se maneja en dos niveles → El servicio devuelve null si no encuentra el autor. El controlador convierte ese null en un error 404.
  • El mismo patrón se repite → Index y Details usan exactamente el mismo patrón: ViewModel → Interfaz → Servicio → Controlador → Vista.
